# 백그라운드 트레이 유지 설계

## 목표

Windows에서 창의 X 버튼을 누르거나 macOS에서 빨간색 닫기 버튼을 눌러도 찐막 프로세스와 롤 감시가 계속 실행되도록 한다. 창은 숨겨지고, Windows 하단 트레이 또는 macOS 상단 메뉴바 아이콘에서 다시 열 수 있어야 한다. 실제 앱 종료는 아이콘 메뉴의 `앱 종료`를 선택했을 때만 수행한다.

## 범위

- 공통 Electron 실행기에 `Tray`와 컨텍스트 메뉴를 추가한다.
- 창 닫기 이벤트를 가로채 일반 닫기를 숨김 동작으로 바꾼다.
- Windows와 macOS에서 동일한 메뉴와 종료 정책을 사용한다.
- 기존 단일 인스턴스, 폴링, 카운트다운, 종료 전 정리 로직은 유지한다.
- 트레이 아이콘을 클릭하거나 `찐막 열기`를 선택하면 창을 표시하고 포커스한다.

## 동작 설계

### 수명주기

1. 앱 준비가 완료되면 창과 트레이 아이콘을 생성한다.
2. 창의 `close` 이벤트에서 실제 종료 플래그가 없으면 이벤트를 취소하고 창을 숨긴다.
3. 창이 숨겨져도 컨트롤러 폴링과 타이머는 계속 실행한다.
4. 카운트다운이 시작되면 기존처럼 창을 복원하고 포커스한다.
5. 트레이 메뉴의 `앱 종료`는 실제 종료 플래그를 세운 뒤 `app.quit()`을 호출한다.
6. `before-quit`에서 기존 타이머, 컨트롤러, 플랫폼 어댑터를 정리하고 트레이 객체를 해제한다.

트레이 아이콘은 별도 배포 파일에 의존하지 않고 공통 실행기에서 작은 인라인 SVG를 `nativeImage`로 변환해 만든다. 아이콘은 기존 찐막의 전원 버튼 의미를 사용하며, macOS 메뉴바에서도 식별 가능한 단순한 형태로 유지한다.

### 메뉴

- `찐막 열기`: 숨겨진 창을 복원하고 표시한다.
- 구분선
- `앱 종료`: 실제 앱 종료를 수행한다.

Windows에서는 트레이 아이콘의 기본 클릭 동작도 창을 여는 동작으로 연결한다. macOS에서는 상단 메뉴바 아이콘과 메뉴를 통해 같은 동작을 제공한다.

### 예외 및 기존 종료 경로

- 단일 인스턴스 락을 얻지 못한 경우 기존처럼 즉시 종료한다.
- 지원하지 않는 플랫폼의 실제 실행, 앱 준비 실패 등 초기화 실패 경로는 기존처럼 종료한다.
- 인라인 트레이 아이콘 생성이 실패하면 앱 시작을 실패시키지 않고 창 닫기 정책은 유지한다.

## 구현 경계

`packages/desktop/src/main.cjs`가 창, 트레이, 앱 종료 플래그를 소유한다. Windows/macOS 진입점과 플랫폼 어댑터에는 변경을 추가하지 않는다. 테스트 가능한 창 닫기 정책은 작은 순수 함수 또는 명시적인 이벤트 핸들러 경계로 분리해 Electron 객체를 직접 띄우지 않고 검증한다.

## 검증 계획

- 정적/단위 테스트: 닫기 이벤트가 일반 상태에서는 취소되고 숨김 처리되며, 실제 종료 상태에서는 닫기를 허용하는지 확인한다.
- 회귀 테스트: 기존 `npm test`가 통과하는지 확인한다.
- UI 스모크 테스트: 모의 앱에서 창을 닫은 뒤 Electron 앱이 살아 있고, 트레이 메뉴 또는 재표시 경로로 창을 열 수 있는지 확인한다. 플랫폼별 실제 네이티브 트레이 표시 여부는 해당 운영체제에서 별도로 확인한다.
- README와 화면 하단 안내 문구를 새 동작에 맞게 수정한다.

## 제외 사항

- 로그인 시 시작, 트레이 아이콘 알림, 시스템 알림, 자동 업데이트는 추가하지 않는다.
- 창을 닫을 때 확인 대화상자를 표시하지 않는다.
- 기존 게임 감시 및 PC 종료 로직의 동작은 변경하지 않는다.
